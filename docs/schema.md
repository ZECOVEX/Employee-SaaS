# Database Schema

All tenant tables carry `organization_id` (FK → organizations, cascade delete) unless noted.

## organizations
| Column | Notes |
|---|---|
| id, name, slug (unique), timezone, status (`active`/`suspended`), timestamps | Tenancy root |
| settings (json, nullable) | Per-org knobs: `debounce_seconds` (punch debounce window, 5–300, default 15), `time_format` (`24h` default → 16:00 / `12h` → 4:00 PM; drives every clock display via `Organization::formatTime()` and the `<x-time>` component), plus salary rules (`currency`, `late_deduction` `per_minute`/`none`, `deduction_grace_minutes` 0–240, `deduction_rounding` `exact`/`nearest`/`whole`, `absence_deduction` `full_day`/`half_day`/`none`, `half_day_deduction`, `unpaid_leave_deduction` bool, `max_deduction_percent` 0–100 — defaults in `Organization::salaryRules()`) |

## users (tenant-scoped but NO global scope)
| Column | Notes |
|---|---|
| organization_id | null only for platform admins |
| name, email (unique), password, remember_token | Breeze auth |
| must_change_password | boolean default false — set by admin/manager password resets and admin-created users; drives the app-wide banner + PasswordChangeRequired notice until the profile form or email reset link clears it |
| mfa_enabled | boolean default false (Phase 8) — when true, the login flow stages a TOTP/recovery-code challenge before the session is granted |
| mfa_secret | text nullable, **encrypted cast** (Phase 8) — base32 TOTP secret generated by `MfaService::beginSetup`, revealed only in the QR/otpauth URL during setup |
| mfa_recovery_codes | json nullable, array cast (Phase 8) — 8 one-time codes, stored **sha256-hashed**; consumed by `MfaService::consumeRecoveryCode`, regenerable from the profile |
| email_verified_at, last_login_at | |
| is_platform_admin | boolean; bypasses RBAC |

## RBAC tables
- **permissions** — global catalog: `key` (unique), `name`, `group`
- **roles** — per-org: `organization_id`, `name`, `slug` (unique per org)
- **role_permission** — pivot `role_id`/`permission_id`
- **user_role** — pivot `user_id`/`role_id`

## Organization tables
- **departments** — `organization_id`, `name`, `code` (unique per org), `manager_id` (FK users, nullable)
- **positions** — `organization_id`, `department_id` (nullable FK departments, nullOnDelete), `title` (unique per org, validated in the Positions admin UI; no `code` column)
- **employees** — `organization_id`, `user_id` (nullable), `employee_code` (unique per org), `department_id` (nullable), `designation`, `employment_type`, `status`, `joining_date`, `left_date`, `phone`, `address`, `date_of_birth`, `gender`, `salary` (decimal, hidden from index UI in Phase 1), `photo_path` (nullable; `image|max:2048` upload stored on the `public` disk under `employees/{id}/`)
- **audit_logs** — `organization_id`, `actor_user_id`, `action`, `resource_type`, `resource_id`, `old_value` (json), `new_value` (json), `ip_address`, `user_agent`, `created_at`

## Phase 2 — Workforce tables
- **work_schedules** — `organization_id`, `name`, `work_days` (json array of ISO day numbers), `start_time`, `end_time`, `grace_minutes`, `break_start`/`break_end` (nullable), `is_default`, `effective_from`/`effective_to` (nullable dates, indexed) — effective-dated versions (§11): a schedule change closes the current version (`effective_to` = yesterday) and opens a new one (`effective_from` = today), so re-deriving past days resolves the schedule they were worked under; plain index on `organization_id`+`is_default` (multiple historical rows may exist)
- **holidays** — `organization_id`, `name`, `date` (stored `Y-m-d` via `date:Y-m-d` cast), `is_recurring`
- **nfc_cards** — `organization_id`, `employee_id` (nullable), `card_token` (unique), `status` (`active`/`blocked`/`revoked`), `issued_at`, `revoked_at`, `last_used_at`
- **attendance_terminals** — `organization_id`, `name`, `location`, `api_key_hash`, `status` (`active`/`revoked`), `last_seen_at`
- **attendance_events** — `organization_id`, `employee_id`, `terminal_id` (nullable), `nfc_card_id` (nullable), `event_type` (`check_in`/`check_out`/`break_start`/`break_end`/`manual_in`/`manual_out`), `occurred_at`, `timezone`, `source` (`nfc`/`manual`/`api`), `notes`, `created_by`, `superseded_by` (nullable self-FK), `deleted_at` (soft delete) — source of truth; raw rows are never overwritten: an admin correction (§24) creates a replacement event and points the original at it via `superseded_by`, removals are soft-deleted, and derivation/punching only reads active rows (`superseded_by IS NULL AND deleted_at IS NULL`); `occurred_at` + `timezone` hold the **org-local wall-clock as entered/tapped** (no instant conversion — derivation and display compare/format these wall times directly, so UTC+6 orgs never see a +6h shift); daily rows are derived from these
- **daily_attendance** — table name is singular by spec; `organization_id`, `employee_id`, `date` (stored `Y-m-d` via `date:Y-m-d` cast), `first_check_in`, `last_check_out`, `total_work_minutes` (sum of IN→OUT segments, gap-aware break deduction — not first-in→last-out), `late_minutes`, `early_leave_minutes`, `overtime_minutes`, `segment_count` (completed segments that day), `review_flag` (nullable: `possible_missed_checkin` / `excessive_segments`), `status` (`PRESENT`/`LATE`/`ABSENT`/`HALF_DAY`/`LEAVE`/`HOLIDAY`/`WEEKEND`/`REMOTE`), `is_manual`
- **leave_types** — `organization_id`, `name`, `code`, `default_days_per_year`, `is_paid`, `is_active`
- **leave_requests** — `organization_id`, `employee_id`, `leave_type_id`, `start_date`, `end_date`, `days`, `reason`, `status` (`pending`/`approved`/`rejected`/`cancelled`), `reviewed_by`, `review_note`
- **leave_balances** — `organization_id`, `employee_id`, `leave_type_id`, `year`, `total_days`, `used_days` — unique (`employee_id`, `leave_type_id`, `year`)

Defaults seeded per org by `WorkforceDefaults::apply()`: Standard schedule (Mon–Fri 09:00–18:00, 15 min grace) and 5 leave types (ANNUAL 20, SICK 10, CASUAL 10, EMERGENCY 5, UNPAID 0).

## Phase 3 — Compensation tables
- **salary_records** — `organization_id`, `employee_id`, `basic_salary`, `allowances`, `bonus`, `deductions`, `gross_salary`, `net_salary` (decimals 12,2), `effective_from`/`effective_to` (dates; `effective_to` nullable), `notes` (500, nullable), `created_by` (FK users, nullable) — effective-dated (§28): `SalaryRecord::effectiveFor(org, employee, date)` picks the latest row with `effective_from ≤ date` and `effective_to` null-or-≥ date, so a raise never rewrites earlier months (Salary Report and payslips both read through it); index (`organization_id`, `employee_id`, `effective_from`)
- **payslips** — `organization_id`, `employee_id`, `period` (char7 `YYYY-MM`), `period_start`/`period_end`, `revision` (default 1), `currency`; earnings snapshot (`basic_salary`, `allowances`, `bonus`, `other_deductions`, `gross_salary`); attendance-deduction snapshot (`late_deduction`, `absence_deduction`, `unpaid_leave_deduction`, `attendance_deduction_total`, `net_salary`); month-end context §52 (`scheduled_days`, `completed_days`, `worked_minutes`, `late_minutes`, `overtime_minutes`, `daily_rate`, `hourly_rate`, `capped`); `snapshot` (json — full calculator output for reproducibility), `notes`, `superseded_by` (self-FK, nullable), `created_by` (FK users, nullable) — one **active** row per employee+period (`superseded_by IS NULL`, enforced in `PayslipController`); revising bumps `revision` and points the old row's `superseded_by` at the new one inside a transaction, so finalized numbers never move when salary records or rules change later; index (`organization_id`, `employee_id`, `period`)

## Phase 4 — Platform tables
- **notifications** — Laravel default schema: `id` (uuid), `type` (notification class), morph `notifiable_type`/`notifiable_id` (indexed), `data` (text), `read_at` (nullable); written by `App\Notifications\*` classes extending `OrganizationNotification` (via `['database','mail']`, shared mail template `resources/views/mail/notification.blade.php`) for leave status changes, attendance corrections, NFC card status, salary updates, password changes, password-change-required notices (`PasswordChangeRequired`, stays until the flag clears), support ticket arrivals (`SupportTicketCreated`, to admins + department managers), once-per-day late-arrival alerts (`LateArrival`, fired when a day first accrues late minutes), overtime detection/manager-stage/decision events, payslip + monthly-status ready, and risk alerts (`HighRiskAttendance`, `OvertimeLimitNotice`)
- **personal_access_tokens** — Sanctum: `name`, `token` (unique, sha256), `abilities` (json), `last_used_at`, `expires_at` (nullable); issued by `POST /api/v1/auth/login` with a 30-day expiry
- **plans** — platform-wide catalog (no `organization_id`): `slug` (40, unique: `free`/`starter`/`business`/`enterprise`), `name` (60), `employee_limit` (unsigned int, nullable = unlimited), `price_monthly` (decimal 8,2, default 0), `stripe_price_id` (varchar 120, nullable — Phase 9: Stripe price for paid plans, null = Stripe checkout unavailable), `is_active`, timestamps — seeded by `PlanSeeder`
- **subscriptions** — `organization_id` (unique — one subscription per org), `plan_id` (FK plans, cascade), `status` (20, default `active`; values `trial`/`active`/`past_due`/`canceled`), `trial_ends_at` (date, nullable), `current_period_start`, `current_period_end` (dates), `stripe_customer_id` (varchar 120, nullable — Phase 9), `stripe_subscription_id` (varchar 120, nullable — Phase 9, set from `checkout.session.completed` / `customer.subscription.updated`) — `BillingService::provisionDefault()` creates the `free` row at provisioning; `switchPlan()` updates in place and starts a fresh monthly period
- **invoices** — `organization_id` (FK cascade), `plan_id` (FK plans, nullable, null-on-delete), `number` (40, unique, format `INV-{Ym}-{6 random}`), `amount` (decimal 8,2), `currency` (default `USD`), `status` (default `open`; `open`/`paid`/`void`), `period_start`/`period_end` (dates), `paid_at` (date, nullable), timestamps; index (`organization_id`, `status`) — issued on paid-plan selection

## Phase 5 — Overtime, scoring & risk tables
- **overtime_policies** — `organization_id`, `effective_from`/`effective_to` (nullable dates, index `organization_id`+`effective_from`) — effective-dated versions like work_schedules (§11): a policy change closes the old version and opens a new one, so history keeps the policy it ran under; `enabled`, `mode` (`AFTER_OFFICE_END`/`ABOVE_EXPECTED_HOURS`), `start_threshold_minutes` (15), `rounding_minutes` (15) + `rounding_method` (`UP`/`DOWN`/`NEAREST`), caps (`daily_cap_minutes` 120, `weekly_cap_minutes` 720, `monthly_cap_minutes` nullable, `max_shift_minutes` 960), `approval_mode` (`AUTO`/`MANAGER`/`MANAGER_HR`), `pending_expiry_days` (7) + `pending_expiry_action` (`AUTO_APPROVE`/`AUTO_REJECT`/`ESCALATE`), multipliers (`weekday` 1.50, `weekend` 2.00, `holiday` 2.00, optional night window + `night_multiplier`), `rate_base` (`GROSS`/`BASIC`/`CUSTOM`), `offset_late_with_overtime`, `weekend_all_overtime`, `compensation_type` (`PAID`/`COMP_TIME`), `require_pre_approval`, `show_pay_to_employee`, `show_hours_to_employee`, `overtime_score_bonus_max` (score bonus cap, default 0 = off), `created_by` — one effective row per date; a missing/never-saved policy falls back to `OvertimePolicy::defaults()` in code (not a DB row)
- **overtime_records** — `organization_id`, `employee_id`, `work_date` (unique per employee+date), `day_type` (`WORKING_DAY`/`WEEKEND`/`HOLIDAY`/`LEAVE_DAY`), `policy_id` (nullable FK), `worked_minutes`, `expected_minutes`, `raw_minutes`, `late_offset_minutes`, `countable_minutes`, `multiplier`, `hourly_rate_snapshot` (nullable), `estimated_pay`, `status` (`NONE`/`PENDING`/`AUTO_APPROVED`/`APPROVED`/`REJECTED`/`FLAGGED`), `flag_reason`, `employee_note`, `calculated_at` — derived on every attendance change; `countable_minutes` is what approvals, comp-time, risk limits and dashboards count; `daily_attendance.overtime_minutes` mirrors the approved value; indexes (`organization_id`,`status`) and (`organization_id`,`work_date`)
- **overtime_approvals** — `organization_id`, `overtime_record_id` (FK cascade), `approver_user_id` (nullable FK), `decision` (`APPROVED`/`REJECTED`/`ADJUSTED`/`ESCALATED`), `minutes_before`/`minutes_after` (nullable), `reason`, `decided_at` — append-only trail of every decision, adjustment or expiry escalation
- **comp_time_entries** — `organization_id`, `employee_id`, `overtime_record_id` (unique FK), `work_date`, `minutes` — §73-F COMP_TIME ledger (one row per approved record that accrues time off instead of pay); balance = Σ minutes
- **employees** (Phase 5 addition) — `overtime_eligibility` string(16) default `POLICY_DEFAULT` — per-employee override (e.g. exclude salaried managers from overtime)
- **risk_events** — `organization_id`, `employee_id`, `type` (`late_week`/`ot_week`/`ot_month`/`ot_streak`), `level` (configurable label, e.g. `HIGH RISK`), `period_start`/`period_end` (dates), `observed`, `threshold`, `detail` (human summary shown on Statistics/dashboards), `notified_at` (nullable) — unique (`organization_id`, `employee_id`, `type`, `period_start`, `period_end`) so one event exists per evaluation window and repeat notifications are suppressible
- **employee_monthly_statuses** — `organization_id`, `employee_id`, `year`, `month`, `attendance_score`, `attendance_rate`, `punctuality_score`, `working_hours_score`, `leave_score` (decimals 6,2), `days_present`/`days_absent`/`days_late`/`days_on_leave`, `total_work_minutes`/`expected_work_minutes`, `overtime_minutes_approved`/`_pending`/`_rejected`, `overtime_days`, `status`, `generated_at` — §17 finalized month-end snapshot generated by `status:generate`; unique (`organization_id`, `employee_id`, `year`, `month`); existing rows are never rewritten

`organizations.settings` (Phase 5 keys) — `score_weight_attendance|punctuality|working_hours|leave` (defaults 40/25/20/15), `risk_bands` (list of `{min,label}`, strictly descending, lowest min 0), `late_risk_enabled|threshold|period|level|recipients|suppress`, `ot_risk_enabled|weekly_minutes|monthly_minutes|streak_days|level|recipients|suppress` (defaults in `RiskService::defaults()`, read via `RiskService::config()`)

## Phase 8 — Security & integration tables
- **api_keys** — `organization_id` (FK cascade), `name` (80), `prefix` (12 — non-secret lookup prefix shown in the UI, e.g. `emsak_a1b2c3`), `key_hash` (64, unique — sha256 of the full key, never the key itself), `abilities` (json nullable — permission keys or `['*']`; null or `['*']` = all org abilities; `ApiKey::canPermission()` checks membership, `hasAnyRole` is true only for `*`), `last_used_at`, `revoked_at` (nullable), `created_by` (FK users, nullable nullOnDelete), timestamps; index (`organization_id`); full key `emsak_{40 chars}` shown once on create; resolved by the `auth:apikey` guard (`Auth::viaRequest` → `ApiKey::resolveFromRequest` reads `Authorization: Bearer` or `X-Api-Key`)
- **scim_tokens** — `organization_id` (FK cascade), `name` (80), `token_hash` (64, unique — sha256 of `scim_{40}`), `last_used_at`, `revoked_at`, `created_by` (FK users, nullable nullOnDelete), timestamps; index (`organization_id`); resolved by the `auth:scim` guard; `canPermission` grants everything while the token is active (the SCIM routes carry no catalog `permission:` middleware — token presence + org scope is the gate)
- **webhook_subscriptions** — `organization_id` (FK cascade), `url` (500), `events` (json — array of event names, or `['*']`), `secret` (64 — per-subscription HMAC key, shown once on create), `is_active` (boolean default true), `last_delivery_at`, `last_status` (80 — last HTTP code or `failed`), timestamps; index (`organization_id`); `WebhookSubscription::matches($event)` compares against `events`; `WebhookController` rejects localhost / `10.*` / `192.168.*` / `169.254.169.254` targets (SSRF guard)
- **users** (Phase 8 additions) — `mfa_enabled` (boolean), `mfa_secret` (text, encrypted cast), `mfa_recovery_codes` (json array cast of sha256 hashes, 8 codes of 10 chars)

`organizations.settings` (Phase 8 keys) — `sso_enabled` (bool), `sso_name`, `sso_discovery_url` (OIDC discovery base), `sso_client_id`, `sso_client_secret` (stored `encrypt()`ed), `sso_allowed_domains` (array of email domains allowed to authenticate via SSO)

Migrations: `2026_10_11_120000_create_api_tables`, `2026_10_11_120001_create_webhook_subscriptions_table`, `2026_10_11_120002_add_mfa_to_users_table`, `2026_10_11_120003_add_stripe_columns`.

## Phase 6 — No schema changes

Analytics/reporting surfaces (Statistics month/week + OVERTIME sections, overtime report, Monthly Report score/status/overtime columns, analytics overtime trend, dashboard score/[OT]/weekly-summary widgets) are views over Phase 1–5 data: `daily_attendance`, `overtime_records` + `overtime_approvals`, `risk_events`, `employee_monthly_statuses`, salary records/rules. They read existing `organizations.settings` keys (`ot_risk_weekly_minutes`, `ot_risk_monthly_minutes`, `score_weight_*`, `risk_bands`, salary rules) — no new tables or columns.

## Post-Phase 6 — No schema changes

Leave attachments reuse the existing `leave_requests.attachment_path` column (files live on the private `local` disk under `leave-attachments/{orgId}/`, never in the database); global search is a read-only query over existing tables; the Phase 7 payslip and monthly-status notifications use the existing `notifications` table.

## Password recovery (support tickets)
- **support_tickets** — `organization_id` (FK cascade), `user_id` (FK users, nullable nullOnDelete — the matched requester account), `email` (as entered), `subject` (default `Password reset request`), `message` (text, nullable — requester note), `status` (`open`/`resolved`, default `open`), `reply` (text, nullable — staff reply), `resolved_by` (FK users, nullable nullOnDelete), `resolved_at` (nullable), timestamps; index (`organization_id`, `status`) — filed by guests from the forgot-password page (Option 2), visible to `Gate::support.view` holders (admins, managers, department managers), audited as `support.created`/`support.replied`/`support.resolved`

## Stock Breeze tables
- `sessions`, `cache`, `cache_locks`, `jobs`, `job_batches`, `failed_jobs` (framework)
